1. What Works
The core functionality of the Malware Behavior to MITRE ATT&CK Technique Mapper is working end‑to‑end.
✅ JSON Input Processing

The tool successfully reads a structured JSON input file containing malware sample metadata and observed behaviors.
Each observed behavior is correctly parsed and instantiated as an ObservedBehavior object.
The input schema matches the proposal design and sample data exactly.

✅ Core Class Implementation

The ObservedBehavior class represents individual malware behaviors and normalizes timestamps.
The AttackTechniqueMapper class implements rule‑based logic to map observed behaviors to MITRE ATT&CK techniques.
Mapping rules successfully identify:

Process injection–related API calls (CreateRemoteThread, VirtualAllocEx) → T1055
Registry Run key modification → T1547.001
Outbound network connections → T1071



✅ Processing Logic

Observed behaviors are analyzed sequentially.
Matched techniques are collected into a tagged results list.
Technique frequency is calculated correctly across all behaviors.

✅ JSON Output Generation

The tool writes a structured JSON output report containing:

Sample ID
Analysis timestamp
Tagged behaviors with confidence scores
Technique frequency summary
Overall analysis summary statistics


Output format matches the provided example and is suitable for reporting.

✅ Command‑Line Interface (CLI)

The tool runs from the command line using argparse.
Required arguments (--input, --output) are validated correctly.
The --verbose flag enables detailed debug logging.

✅ Logging and Error Handling

Logging clearly reports major stages of execution (loading input, analysis, output writing).
Errors such as missing input files are handled gracefully without crashing.
The tool exits cleanly with meaningful error messages when failures occur.

✅ The program can be demonstrated end‑to‑end in under two minutes.

2. What’s Missing (Planned for Week 15)
The following features are intentionally deferred to maintain a Week 14 MVP scope:

Advanced correlation logic

Behaviors are mapped independently; temporal correlation is not yet implemented.


Dynamic confidence scoring

Confidence values are currently fixed per rule.


Multiple technique mappings per behavior

Each behavior maps to a single primary ATT&CK technique in the MVP.


ATT&CK Navigator export

Output is JSON only; visual mapping will be added later.


Expanded rule set

Only key techniques are implemented to validate the pipeline.



These gaps are known, documented, and planned for Week 15 polishing.

3. Changes from Proposal
Several minor, intentional adjustments were made during implementation:

Simplified rule‑based mapping

The proposal allowed for configurable rules; Week 14 focuses on hard‑coded rules to ensure a working MVP.


Focused scope

The original design mentioned multiple behavior categories; implementation started with the most representative behaviors.


Output refinement

Technique frequency counting was added during implementation to improve analytical value.



These changes were made to prioritize an end‑to‑end working system rather than over‑engineering early.
